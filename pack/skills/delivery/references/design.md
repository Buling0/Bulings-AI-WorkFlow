# 设计阶段规则

协调者维护 `03-design/README.md`（设计总览）。设计基于**已批准且新鲜**的需求与调查，写方案与变化清单。

## 正文结构

```markdown
# 设计

## 方案

用一段话说明选择和取舍。

## 变化

### <变化名>

- 类型：内部整理 或 外部行为
- 场景：<需求里的场景名>
- 行为：
- 不变量：
```

「类型」只能是 **内部整理** 或 **外部行为**。

### 外部行为（供协调者分类，程序只校验字面量）

下列情况应标为「外部行为」：

- 新的独立职责模块
- 公共接口变化
- 跨模块状态归属变化
- 权限或数据安全
- 回滚约定
- 用户能观察到的新错误或新执行顺序

其余整理归「内部整理」。存在任一外部行为变化时，实施前必须完成独立设计评审并记录 `pass`。

## 依赖

在第一次对设计总览 `confirm-change` 之前，运行 `bulings delivery prepare-design`，把设计总览的 `dependencies` 写成需求总览与调查总览，并记录二者当前语义版本。

## 写作边界

- 每个「场景」必须等于需求总览里已有的场景名。
- 事实类型不能冒充：设计不重复长篇调查，不把未验证假设写成结论。
