# 使用 Unity MCP

工程配置了 Unity MCP（`.bulings/workflow.yaml` 的 `unity.mcp`，由 `bulings init` 合并写入 `.cursor/mcp.json`）时，可以通过 MCP 工具直接操作打开的 Unity 编辑器。工具名因所用的 MCP 服务而异，先看有哪些可用工具，不要凭记忆调用。

没有可用的 Unity MCP 工具（服务没启动、没连上）时，如实说明，不要假装已经验证；按原流程只改文件。

## 能做什么

- 读：场景和预制体层级、组件及其序列化字段、控制台日志。
- 编译与刷新：改完脚本后触发刷新，读控制台确认没有编译错误和新增警告。
- 编辑器内操作：创建/修改 GameObject 与组件、绑定预制体上的脚本引用、设置序列化字段、保存预制体、运行 EditMode/PlayMode 测试。

## 边界

- 分析阶段只读，不改场景和资源。
- 实现阶段只改当前任务涉及的预制体、场景对象和脚本。别的对象不碰。
- `protectedPaths` 里的资源不改，MCP 操作同样适用。
- 不改 `.meta` 的 guid。不通过 MCP 删除资源，除非任务明确要求。
- 不通过 MCP 触发批处理构建或打包。
- 用 MCP 改了预制体/场景后，要保存；改动范围写进任务完成时的说明。
- 不创建 git commit。

## 验证

任务完成前：刷新后控制台无编译错误；任务的完成标准里涉及预制体绑定的，用 MCP 回读确认引用不为空。验证没做成的，写进开发说明，不要标成已验证。
