# 四个维度的问法

每轮只推一个维度。这里写每个维度该问到什么深度、选项通常分哪几类、什么算问到点了。

判断标准只有一条：**这轮问完之后，开发者能不能说出"我知道这游戏长什么样了"**。

---

## 一、玩法核心循环（`core`）

**问什么**：玩家每分钟在做什么、为什么愿意再做一遍。

要落到的粒度：

1. 一句话的核心循环：`做A → 得到B → 用B做C → 回到A`，每一环都是玩家动作，不是系统名。
2. 一局 / 一次的边界：多久、怎么结束、失败会怎样。
3. 唯一的核心动词：这个游戏最主要让你按的那个键是什么（建造 / 射击 / 调度 / 组合 / 潜行）。
4. 变化来源：第 1 局和第 10 局有什么不同（关卡、随机、解锁、数值成长）。

常见选项分叉：

- 循环形状：回合制 vs 实时；连续经营 vs 关卡制；单人挑战 vs 环境对抗。
- 失败成本：立刻重来 vs 保留进度；惩罚型 vs 温和型。
- 变化来源：程序生成 vs 手工关卡；解锁驱动 vs 数值驱动。
- 操作密度：一局一次决策 vs 每秒都要操作。

别在这一轮就问剧情、美术风格，也别写数值表。

---

## 二、剧情与世界观（`story`）

**问什么**：要不要剧情、剧情怎么和玩法咬合、说多少。

要落到的粒度：

1. 有没有剧情：纯系统驱动 / 轻叙事（环境与文本碎片）/ 线性主线 / 分支叙事。
2. 剧情怎么进玩法：只在关卡间播 / 影响目标与机制 / 完全独立。
3. 世界观一句话：玩家在哪、为什么在这、失败意味着什么。
4. 主要角色数量级和身份，以及是否需要台词。

常见选项分叉：

- 有剧情 vs 无剧情（把"无剧情"也做成一个正经选项，写清省了什么、丢了什么）。
- 叙事载体：关卡间文本 vs 场景内环境叙事 vs 角色对话。
- 主线强弱：一条主线走到黑 vs 松散事件 vs 玩家自述。

如果玩法还没定死，先别把剧情写深——剧情定太早会把玩法锁死。

---

## 三、美术风格与音频（`style`）

**问什么**：玩家看到和听到的是什么，工作量在不在一个人能扛的范围里。

要落到的粒度：

1. 视角与维度：2D 顶视 / 2D 侧视 / 2.5D / 3D 第三人称 / 3D 固定视角。
2. 视觉气质：用能对照的说法（低多边形、像素、手绘水彩、粗描边卡通、单色调＋撞色），不要"精美""有质感"。
3. 关键资产清单的量级：需要几种角色、几种地形、几种特效（用数量级，如"5-8 种敌人"）。
4. 音频基调：有没有 BGM、音效风格、要不要配音。

常见选项分叉：

- 视角：顶视 vs 侧视 vs 固定斜 45°——直接影响操作和关卡设计成本。
- 资产路线：极简几何 / 像素 / 手绘 / 采购现成资源包。
- 表现重心：角色动画 vs 场景氛围 vs 特效反馈（三者里选一个重点，其余克制）。

风格选项必须写清美术工作量代价，这是小团队最容易翻车的地方。

---

## 四、游戏流程与关卡节奏（`flow`）

**问什么**：从打开游戏到退出，玩家经过什么；内容量的真实规模。

要落到的粒度：

1. 一局的完整进程：进入 → 前 5 分钟 → 中期 → 收尾 / 失败 → 重开。
2. 结构：单局制 / 关卡列表 / 开放探索 / 章节推进。
3. 节奏：什么时候给新东西（新机制、新敌人、新目标），大概多久给一次。
4. 内容量级：关卡数、时长预期、可重复内容占比。
5. 开局体验：第一次打开游戏的前 3 分钟，玩家必须经历什么、看到什么。

常见选项分叉：

- 结构：10 个手工关卡 vs 无限程序关卡 vs 一个可反复玩的场景。
- 单局时长：5 分钟一局 vs 30 分钟一局。
- 节奏密度：每关一个新机制 vs 每三关一个新机制。
- 开局方式：直接进玩法 vs 教学关 vs 剧情开场。

这一轮之后，如果四个维度都确认了，让开发者用 `--finish` 定稿；还没想清的，继续用 `--note` 补充或重复这一轮。

## 五、写选项的通病

| 通病 | 表现 | 怎么改 |
| --- | --- | --- |
| 假选项 | "A：轻量；B：轻量但更灵活；C：全都要" | 让三个选项在玩家体验上明显不同，并各自写清代价 |
| 措辞差异 | "打击感强" vs "手感好" | 落到具体机制：有没有命中停顿、有没有击退 |
| 替开发者决定 | 正文里直接写"采用 Roguelite" | 把决定变成选项，正文等选完再写 |
| 越界 | 玩法轮就开始定怪物数量和数值 | 每个维度只推自己的深度，其他留到后面 |
| 假深度 | 写了 10 个系统，核心循环还是空的 | 先把一圈循环闭合，再谈系统 |
