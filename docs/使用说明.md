# Bulings AI WorkFlow 使用说明

面向使用者的上手文档。命令参数的完整列表见 [README](../README.md)。

## 1. 它能做什么

| 能力 | 入口 | 适用场景 |
| --- | --- | --- |
| 工作模式 | `bulings run` / `resume`，或 Cursor 对话 | 一份策划案 + 若干预制体，拆成任务后逐项写代码 |
| 前端分离 | `bulings split`，或 Cursor 对话 | 策划案里客户端、服务端混写，只想开发客户端部分 |
| Unity MCP | `bulings init` 自动配置 | 让 Agent 直接操作打开的 Unity 编辑器 |
| 交付流 | `bulings delivery ...` | 跨多轮、需要独立评审和验证的长任务（见 [交付任务文档](delivery-tasks/00-索引与共同约定.md)） |

局部小改不需要走这套流程，直接在编辑器里改。独游模式（`mode: indie`）只保留入口，调用时会停止。

## 2. 准备

- Python 3.10+，环境变量 `CURSOR_API_KEY`（Cursor Dashboard → Integrations 的用户 API key）。
- 一个 Unity 工程（目录下有 `Assets` 和 `ProjectSettings`）。
- 若要用 Unity MCP：在 Unity 里安装并启动一个 MCP 插件，并确认它的服务地址。

在本仓库根目录安装：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
$env:CURSOR_API_KEY = "cursor_..."
```

## 3. 装进 Unity 工程

```powershell
bulings init --project <Unity工程>
```

会做三件事：

1. 把 Skill（`work-feature`、`client-split`、`delivery` 等）复制到 `<工程>/.cursor/skills/`，重复执行会更新。
2. 工程里没有 `.bulings/workflow.yaml` 时写入示例配置，已有则保留。
3. 按配置把 Unity MCP 合并写入 `<工程>/.cursor/mcp.json`（同名条目不覆盖）。

升级本仓库后，对每个工程重新执行一次 `init` 即可更新 Skill。

## 4. 典型流程

### 4.1 直接开发整份策划案

```powershell
bulings run --project <工程> --design <策划案> --prefab <预制体> [--prefab ...] [--name <功能名>]
```

流程：分析（出 `tasks.json` 和开发说明）→ 每轮只做一项任务 → 全部完成后写功能说明。

- 任务阻塞或被中断后，用 `bulings resume --project <工程> --run <功能名>` 继续。
- 不想要文档：加 `--no-dev-spec` / `--no-feature-doc`；想改路径：`--dev-spec` / `--feature-doc`。
- 退出码：`0` 完成，`1` 没启动，`2` 已启动但没做完。

### 4.2 只开发客户端部分（前端分离）

```powershell
bulings split --project <工程> --design <策划案> [--name <功能名>] [--output <路径>]
```

1. Agent 逐条把策划案归类为客户端 / 服务端 / 配置 / 待确认，写出客户端需求文档（默认 `Docs/AI/ClientSpecs/{feature}.md`）。
2. **人工看一遍「待确认」和「已排除」**：确认没有漏项、归属没有错。必要时直接改文档。
3. 把这份文档当策划案开发：

```powershell
bulings run --project <工程> --design Docs/AI/ClientSpecs/<功能名>.md --prefab <预制体>
```

在 Cursor 对话里也可以说：“用 client-split 把 `<策划案>` 的客户端部分分离出来。”

### 4.3 在 Cursor 对话里用

用 Cursor 打开 Unity 工程，直接给出策划案和预制体路径。提示里点名阶段或任务编号就只做那一段，例如“只做分析”“只重做 T3”“只写功能说明”。没点名则按顺序一次做一项。

## 5. 使用 Unity MCP

配置在 `.bulings/workflow.yaml`：

```yaml
unity:
  mcp:
    enabled: true
    server: unity
    url: http://localhost:8080/mcp   # 按所用插件改
    command: ""                       # stdio 方式：填命令和 args，并清空 url
    args: []
```

- 默认地址是常见 Unity MCP 插件的假设值，**请核对你实际用的插件**。
- 改了配置后重新执行 `bulings init`。已存在同名条目不会被覆盖，要换地址就直接改 `.cursor/mcp.json`。
- 使用前在 Unity 里启动 MCP 服务，并保持编辑器打开。
- Agent 会用它：读场景/预制体层级、刷新编译、读控制台、绑定预制体引用。分析阶段只读。
- 连不上时 Agent 会说明，不会假装验证；此时只能按文件层面改动，编译和绑定需要你自己确认。

## 6. 配置速查

`.bulings/workflow.yaml`，空字符串和空数组表示未配置：

| 项 | 作用 |
| --- | --- |
| `mode` | `work` 或 `indie` |
| `model` | 默认模型，可被 `--model` 覆盖 |
| `docs.devSpec` / `docs.featureDoc` | 开发说明、功能说明的开关和路径，`{feature}` 为功能名 |
| `clientSplit.path` | 客户端需求文档路径 |
| `unity.mcp` | Unity MCP 服务 |
| `project.*` | 代码目录、命名空间、asmdef、UI 框架、架构、风格；未配置的项由 Agent 从工程推断 |
| `project.protectedPaths` | 这些路径 Agent 不允许改（MCP 操作同样适用） |

## 7. 产物位置

| 产物 | 位置 |
| --- | --- |
| 任务列表 | `.bulings/runs/<功能名>/tasks.json` |
| 运行状态 | `.bulings/runs/<功能名>/state.json` |
| 客户端需求文档 | `Docs/AI/ClientSpecs/<功能名>.md` |
| 开发说明 | `Docs/AI/DevSpecs/<功能名>.md` |
| 功能说明 | `Docs/AI/Features/<功能名>.md` |

## 8. 常见问题

- **提示“不是 Unity 工程”**：`--project` 要指向含 `Assets`、`ProjectSettings` 的目录。
- **提示“还没有 Skill”**：先执行 `bulings init`。
- **提示“已有未完成的运行”**：同一功能还有没做完的运行，用 `resume` 继续。
- **任务一直 blocked**：看 `tasks.json` 里的 `blockedReason`，多半是策划案与预制体对不上。补充信息或修正文档后 `resume`。
- **`split` 后没有输出文件**：命令会以退出码 `2` 结束，检查 Agent 输出，重新执行。
- **Agent 没有用到 MCP**：检查 `.cursor/mcp.json` 里有无对应条目，以及 Unity 里的服务是否在运行。

## 9. 边界

所有流程都不会自动创建 git commit，不改 `.meta` 的 guid，不启动 Unity 批处理编译，不改 `protectedPaths`。生成的代码和文档请自行审阅后再提交。
