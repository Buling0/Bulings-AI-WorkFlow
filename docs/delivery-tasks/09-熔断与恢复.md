# 09 熔断与恢复

先读 [00-索引与共同约定](00-索引与共同约定.md)。前置是 [08-候选与独立评审](08-候选与独立评审.md)。

## 目标

契约边界失效时停止继续改代码，并在原范围重试或人工恢复基线后释放。用户明确撤销本轮实施时，只恢复这次租约范围内的启动基线。只漏登记文件、且调用者声明仍属原业务授权时，可以保留字节并扩大记录范围。

## 本任务产出

- `references/circuit.md`
- `open-circuit`、`resolve-slice`、`interrupt-slice`、`amend-scope`
- `tests/test_delivery_circuit.py`

不自动 `git reset`，不删除范围外文件。

## 熔断

```powershell
bulings delivery open-circuit --project <工程> --feature-id <id> --execution-id impl-1 --rule <规则标识> --summary <失效假设>
```

`--rule` 只能是：

| 标识 | 含义 |
|---|---|
| `acceptance-changed` | 业务结果或验收实质变化 |
| `scope-required` | 范围外路径变成必须修改 |
| `dependency-lost` | 强依赖失效 |
| `shared-data` | 必须改公共或已有存量数据 |
| `invariant-broken` | 必须破坏不变量 |
| `not-independent` | 不能再单独验收 |
| `rollback-lost` | 不能安全退回 |
| `package-rule` | 任务包新增字段 `circuitRules` 里声明的规则 |

任务包的 `circuitRules` 是字符串数组，可为空。`package-rule` 要求 `--summary` 开头包含其中一条原文。

执行标识必须持有 `active` 租约。成功后租约 `status` 变为 `circuit_open`，并在 `05-implementation/circuits.jsonl` 追加一条记录。此后 `checkpoint-slice` 和 `submit-slice` 失败，`code` 为 `CIRCUIT_OPEN`。已有文件和检查点保留。

验证结果为 `failed` 的检查点不会自动调用本命令。

## 收敛

```powershell
bulings delivery resolve-slice --project <工程> --feature-id <id> --action retry --execution-id impl-2
bulings delivery resolve-slice --project <工程> --feature-id <id> --action release
```

只在 `circuit_open` 时可用。

`retry` 要求新的执行标识，且与已用过的实施标识不同。租约回到 `active`，`executionId` 换成新值，`packageDigest` 和 `baseline` 不变。旧检查点保留。新标识可以再记检查点并提交。

`release` 前，范围内每个文件必须与 `baseline.files` 一致：当时存在的文件字节相同，当时不存在的路径现在仍不存在。不一致时失败，`code` 为 `BASELINE_DIRTY`，并列出路径。一致时删除租约，切片状态变为 `released`。该切片不再是 `ready`，也不能再次 `start-slice`。要换一条切片时，调用者按任务 06 批准新版本方案；新方案可以不再包含这个 `released` 标识。若新方案仍包含它，`start-slice` 拒绝，`code` 为 `SLICE_RELEASED`。

## 撤销本轮

```powershell
bulings delivery interrupt-slice --project <工程> --feature-id <id> --execution-id impl-1
```

只在租约 `active` 且执行标识匹配时可用。`in_review`、`circuit_open` 时拒绝。

行为：

- 对 `existed: true` 的范围内文件，把启动时复制下来的字节写回。因此 `lease.json` 的 `baseline.files` 在本任务改为同时保存 `bytesPath`。启动切片时把字节复制到 `.bulings/deliveries/<feature-id>/baselines/<execution-id>/<相对路径>`。
- 对 `existed: false` 且位于范围内的路径，若现在是文件，则删除该文件。不删除范围外路径。
- 删除租约，切片状态变为 `interrupted`。
- 相同执行标识重复调用，在租约已经不存在且范围内文件已与基线一致时返回 `unchanged`。

复制基线时保持相对目录。不要把这些字节提交到 Unity 工程的 Git。

`interrupted` 的切片可以用新的执行标识再次 `start-slice`，新的基线按再次启动时的工作区重新记录。

## 补登记范围

```powershell
bulings delivery amend-scope --project <工程> --feature-id <id> --execution-id impl-1 --path Assets/Scripts/Reward/RewardView.cs.meta --reason 生成器写出了元文件 --authorization 仍属于展示奖励
```

`--path` 可重复。仅当租约是 `circuit_open` 且规则是 `scope-required` 时可用。每个路径都必须是当前越界文件，不能是目录。`reason` 和 `authorization` 非空。

成功后：

- 这些路径追加进任务包 `writeScope` 和租约副本。任务包摘要变化，租约记下 `amendedPackageDigest`。
- 不把这些文件的当前字节当作启动基线。`baseline.files` 对新增路径记 `existed` 为它们在原启动时是否存在；原启动时不存在则 `existed: false`。
- 契约版本字段 `contractVersion` 从 1 开始，每次补登记加 1。
- 租约回到 `active`，但执行标识必须由调用者同时传入一个新的 `--next-execution-id`。旧标识不能再提交。
- 切片状态回到可提交。下一次候选文件要包含这些路径，即使之后没有再改它们。

补登记不替代升版本的切片方案。路径所代表的行为已经超出原验收时，调用者应使用 `release` 和新方案，而不是本命令。程序无法判断业务是否超出，它只检查路径确实越界、理由字段非空、以及调用者使用了 `scope-required`。

## 规则

`references/circuit.md` 写明：测试失败先继续修；只有上表规则成立才熔断。`release` 前由协调者把范围内文件恢复到基线，命令只负责核对。`interrupt-slice` 会替范围内文件恢复字节。

## 测试

- `failed` 检查点之后仍可再记 `passed` 并提交。
- `open-circuit` 后提交失败，`retry` 后新标识可以提交。
- 范围内文件与基线不一致时 `release` 失败；恢复字节后 `release` 删除租约。
- `interrupt-slice` 把修改过的范围内文件恢复成启动副本，并删除启动后新增的范围内文件，范围外文件保持被测试改过的内容。
- `amend-scope` 拒绝目录参数；接受一个越界文件后，新执行标识可以把它包含进候选。
- `circuit_open` 时 `interrupt-slice` 失败。
