# 08 候选与独立评审

先读 [00-索引与共同约定](00-索引与共同约定.md)。前置是 [07-写入租约](07-写入租约.md)。

## 目标

实施者在租约内记录检查点并提交候选。候选固定的是启动基线之后、范围内的真实变化。另一个执行标识才能评审。评审通过后释放租约，后置切片才变得可启动。

## 本任务产出

- `references/checkpoint.md`、`references/review.md`
- `checkpoint-slice`、`submit-slice`、`review-prompt`、`review-slice`
- `tests/test_delivery_review.py`

熔断、中断回基线和界面验收不在本任务。范围内验证失败时，提交命令拒绝，租约保持 `active`。

## 工作区检查

提交和评审前都做同一套比较，函数名可以是 `inspect_lease_workspace`。

范围内：

- 启动时 `existed: true` 的文件，摘要可以变化。
- 启动时 `existed: false` 的路径，现在可以存在。
- 范围内新出现、但路径不落在 `writeScope` 的文件算越界。

范围外：

- `outside` 里记录过的文件，摘要必须相同。
- 启动后新出现的范围外文件、或原先干净而现在内容变化的跟踪文件，算越界。
- 启动时已经脏、且摘要未变的范围外文件，允许继续保持原样。

`.meta` 文件如果在范围内，提交时解析其中的 `guid:`。启动时把 guid 记进 `baseline.files[<path>].guid`。guid 变化则失败，`code` 为 `META_GUID_CHANGED`。不要改这个文件来“修好”它。

越界时 `code` 为 `WORKSPACE_SCOPE_VIOLATION`，`blockers.path` 列出相对路径。不回滚，不释放租约。

## 检查点

```powershell
bulings delivery checkpoint-slice --project <工程> --feature-id <id> --execution-id impl-1 --summary <本轮做了什么> --validation-result passed
```

`--validation-result` 为 `passed`、`failed`、`unverified`。`summary` 非空。执行标识必须等于租约。工作区越界时拒绝写入检查点。

记录追加到 `05-implementation/checkpoints.jsonl`，每行一个 JSON：`executionId`、`sliceId`、`summary`、`validationResult`、`createdAt`。失败结果也追加。重复提交完全相同的摘要、结果和相同工作区范围内摘要时返回 `unchanged`，不追加第二行。

## 提交候选

```powershell
bulings delivery submit-slice --project <工程> --feature-id <id> --execution-id impl-1
```

条件：

- 租约状态是 `active`，执行标识匹配。
- 至少有一条该执行标识的检查点，且最后一条 `validationResult` 是 `passed`。
- 任务包里的每条 `validation` 字符串都在某条 `passed` 检查点的 `summary` 或额外字段中出现。为实现这一点，检查点增加可选数组 `coveredValidation`。最后一条通过的检查点必须用它覆盖任务包 `validation` 的全部条目。
- 工作区检查通过。
- 范围内相对基线至少有一处变化。没有任何变化时失败，`code` 为 `EMPTY_CANDIDATE`。

成功后把租约 `status` 改为 `in_review`，并写 `05-implementation/candidates/<candidate-id>.json`。`candidate-id` 为 `c-<slice-id>-<从 1 开始的序号>`。内容含切片、执行标识、任务包摘要、方案版本和摘要、范围内每个变化文件的当前摘要、`createdAt`。之后范围内摘要再变化，评审必须失败。

## 评审

```powershell
bulings delivery review-prompt --project <工程> --feature-id <id> --candidate-id <id>
```

提示包含：角色是候选评审；候选文件路径；任务包路径；需求总览、设计总览、计划总览的路径；要求结论为 `pass`、`fail` 或 `unverified`；禁止修改文件；禁止阅读协调者对话。提示里不要写实施者的 `executionId` 以外的对话内容。命令不启动 Agent。

```powershell
bulings delivery review-slice --project <工程> --feature-id <id> --candidate-id <id> --execution-id review-1 --decision pass --summary <结论>
```

评审执行标识不得等于候选的实施执行标识，否则 `code` 为 `REVIEW_NOT_INDEPENDENT`，候选保持 `in_review`。

工作区范围内摘要与候选文件不一致时，`code` 为 `CANDIDATE_CHANGED`，不记录通过。

`pass` 时：

- 追加 `05-implementation/reviews.jsonl`。
- 租约文件改为不存在。用替换方式删除，避免留下半份租约。
- 切片在 `05-implementation/slice-state.json` 中记为 `accepted`，并保存候选标识。
- 任务 06 的 `eligibility` 改为：前置切片和被替代切片都已 `accepted` 时，目标切片为 `ready`。

`fail` 或 `unverified` 时租约回到 `active`，仍由原实施执行标识持有，切片状态为 `changes_requested`。不创建新的执行标识。返修身份在任务 09 分配。

`status` 的 `lease` 在评审通过后为 `null`。增加 `slices` 数组，每项含 `id`、`state`（`pending`、`active`、`in_review`、`accepted`、`changes_requested`）、`eligibility`。

## 规则

`references/checkpoint.md` 规定：最后一条检查点要覆盖任务包里的全部验证说明；验证失败时继续在原执行标识下修改，并再记检查点。

`references/review.md` 规定：评审对话只使用 `review-prompt` 的文本；通过表示范围内变化符合需求和设计；评审者不扩大写入范围。

## 测试

- 范围内修改并记通过检查点后可以提交；范围外新文件使提交失败且租约仍在。
- 没有内容变化时提交失败。
- 用实施执行标识评审，得到 `REVIEW_NOT_INDEPENDENT`。
- 提交后改范围内文件，评审得到 `CANDIDATE_CHANGED`。
- 独立标识 `pass` 后租约消失，依赖它的切片从 `waiting` 变为 `ready`。
- `fail` 后原执行标识仍持有 `active` 租约。
- 范围内 `.meta` 的 guid 被改掉时提交失败。
