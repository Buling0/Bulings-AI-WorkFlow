# 07 写入租约

先读 [00-索引与共同约定](00-索引与共同约定.md)。前置是 [06-切片方案](06-切片方案.md)。

## 目标

一个交付流在任意时刻只允许一个切片修改 Unity 工程。启动时记录写入范围和基线。范围是具体的相对路径，程序据此判断以后的提交是否越界。

## 本任务产出

- `references/slice-start.md`
- 任务包草稿、契约检查、`start-slice`
- 租约文件 `.bulings/deliveries/<feature-id>/lease.json`
- `tests/test_delivery_lease.py`

候选、评审和熔断在后续任务。本任务的启动只把切片标为 `active` 并写下基线。

## 任务包

```powershell
bulings delivery prepare-task-package --project <工程> --feature-id <id> --slice-id <slice-id>
```

写入 `05-implementation/packages/<slice-id>.json`。文件已存在则返回 `unchanged` 和现有路径，不覆盖。

调用者编辑后的合同：

```json
{
  "schema": 1,
  "featureId": "building-interaction",
  "sliceId": "show-reward",
  "planVersion": 1,
  "planDigest": "sha256:...",
  "writeScope": ["Assets/Scripts/Reward/RewardView.cs"],
  "acceptance": ["打开界面能看到奖励数量"],
  "validation": ["dotnet test 或项目里实际使用的一条命令说明"],
  "rollback": "恢复本切片启动时的范围内文件"
}
```

`writeScope` 至少一项。每项是工程相对路径，使用 `/`，不含 `.`、`..`、盘符、通配符。目录以 `/` 结尾，表示包含其子路径。文件不以 `/` 结尾。

`protectedPaths` 来自 `.bulings/workflow.yaml`。范围中的任何路径等于或落在保护路径下都非法。`.bulings/` 不能进入范围。

`acceptance` 和 `validation` 各至少一项非空字符串。

## 契约检查

```powershell
bulings delivery check-task-package --project <工程> --feature-id <id> --slice-id <slice-id>
```

通过条件：

- 方案已批准，`planVersion` 与 `planDigest` 等于当前批准。
- 切片在方案里，且按任务 06 的规则 `eligibility` 为 `ready`。任务 08 之后，已接受切片会使后置切片变为 `ready`；本任务先只实现 06 的规则。
- 需求批准和 `design-ready` 有效，计划总览新鲜。
- 写入范围合法，且与保护路径不相交。
- 已有活动租约时失败，`code` 为 `LEASE_HELD`，即使租约属于同一交付项。

成功返回 `packageDigest`，算法同任务 06 的规范化 JSON 摘要。

## 启动

```powershell
bulings delivery start-slice --project <工程> --feature-id <id> --slice-id <slice-id> --execution-id impl-1
```

再次执行检查。工程不是 Git 工作区时失败，`code` 为 `GIT_REQUIRED`。

`execution-id` 匹配 `^[a-z0-9][a-z0-9-]{0,63}$`。启动成功后写入 `lease.json`：

```json
{
  "schema": 1,
  "featureId": "building-interaction",
  "sliceId": "show-reward",
  "executionId": "impl-1",
  "packageDigest": "sha256:...",
  "status": "active",
  "startedAt": "2026-10-27T00:00:00+00:00",
  "baseline": {
    "gitHead": "<rev-parse HEAD，没有提交时为空字符串>",
    "files": {
      "Assets/Scripts/Reward/RewardView.cs": {
        "existed": true,
        "sha256": "sha256:<启动时字节>"
      }
    },
    "outside": {
      "Assets/Scripts/Other.cs": "sha256:<启动时已跟踪或已存在的工作区文件摘要>"
    }
  }
}
```

`files` 记录范围内每个已存在文件的字节摘要；范围内尚不存在的路径记 `existed: false`，不记摘要。目录范围要展开启动时已存在的文件。

`outside` 记录启动时 Git 已显示为修改或未跟踪的文件摘要，路径落在范围内的不放进 `outside`。未修改的跟踪文件不放进 `outside`。实现时用 `git status --porcelain=v1 -z` 和 `git hash-object`，不要 `git add`，不要改暂存区。

同一 `execution-id`、同一 `packageDigest`、且工作区范围内文件摘要仍等于这次租约时，重复 `start-slice` 返回 `unchanged`。任一不同则失败，`code` 为 `LEASE_CONFLICT`，不替换租约。

`status --feature-id` 增加 `lease`：无租约时为 `null`，有租约时给出 `sliceId`、`executionId`、`status`。不把 `baseline` 放进默认状态。

`references/slice-start.md` 告诉实施者：只改 `writeScope`；完成验证前不要声称切片完成；本任务还没有提交候选的命令，改完代码后停住并保留租约。

## 全局占用

`delivery status` 不带标识时，增加 `lease`。有活动租约时给出 `featureId`、`sliceId`、`executionId`；没有时为 `null`。第二个交付项的 `start-slice` 看到非空全局租约时返回 `LEASE_HELD`。

## 测试

使用临时 Git 仓库，里面放一个 Unity 工程结构。

- 保护路径和通配符被检查拒绝，不产生租约。
- 启动后 `lease.json` 的范围内摘要等于文件字节。
- 第二个切片或第二个交付项不能启动。
- 相同参数重复启动返回 `unchanged`，`startedAt` 不变。
- 改了范围内文件后再用同一执行标识启动，返回 `LEASE_CONFLICT`，原基线摘要仍是旧值。
- 没有 `.git` 时失败且没有 `lease.json`。
- 命令不产生新的 Git 提交，`git status` 不因为命令本身而多出暂存项。租约文件位于 `.bulings/`，测试可以在启动前把 `.bulings/` 写进 `.gitignore`。
