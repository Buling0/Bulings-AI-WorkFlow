# 11 本地快照

先读 [00-索引与共同约定](00-索引与共同约定.md)。前置是 [01-交付档案初始化](01-交付档案初始化.md)。恢复执行中的切片时，还要遵守 [09-熔断与恢复](09-熔断与恢复.md) 的租约状态；若 09 尚未实现，本任务的恢复命令在发现 `lease.json` 存在时直接失败，`code` 为 `LEASE_ACTIVE`。

## 目标

每个交付项有一个旁路 Git 库，用来保存档案和范围内文件的快照。它不切换 Unity 工程的分支，不执行 `git add` 到工程仓库，也不推送远端。

## 本任务产出

- `references/snapshot.md`
- `snapshot-save`、`snapshot-list`、`snapshot-restore`
- `tests/test_delivery_snapshot.py`

## 库的位置

```text
.bulings/deliveries/<feature-id>/snapshots.git
```

这是一个 `git init --bare` 之后由命令维护的非裸仓库也可以；要求是它自己的工作树不在 Unity 工程根目录。推荐实现：裸库加临时工作树。临时工作树放在系统临时目录，结束后删除。

快照提交的根目录包含：

- `archive/`：当时 `.bulings/deliveries/<feature-id>/` 下除 `snapshots.git` 和 `baselines/` 以外的文件。
- `scope/`：仅当存在活动或评审中的租约时，复制 `writeScope` 内的当前文件。没有租约时不带 `scope/`。

不要把 Unity 工程里范围外的文件放进快照。

## 保存

```powershell
bulings delivery snapshot-save --project <工程> --feature-id <id> --reason stage-start --stage requirements
```

`--reason` 为 `stage-start`、`before-overwrite`、`stage-submitted`、`stage-completed`、`pause`、`manual`。

`stage-start`、`stage-submitted`、`stage-completed` 还要 `--stage`：`requirements`、`investigation`、`design`、`plan`、`implementation`、`validation`。

`--name` 可选，供 `manual` 使用。每次成功产生新的提交。提交说明第一行是 `<reason> <stage 或 name>`。提交正文保存 JSON：`featureId`、`reason`、`stage`、`name`、`createdAt`。

同一命令在进程中断后可以重跑。若最后一次提交的正文 JSON 与这次参数和当前文件树摘要都相同，返回 `unchanged` 和原提交。文件树摘要是快照根的 `git write-tree` 结果。

失败时工程仓库的 `HEAD`、分支和暂存区与调用前一致。测试用 `git rev-parse HEAD` 和 `git diff --cached --name-only` 证明这一点。

## 列表

```powershell
bulings delivery snapshot-list --project <工程> --feature-id <id>
```

按提交时间倒序返回 `id`（完整哈希）、`reason`、`stage`、`name`、`createdAt`、`subject`。没有快照时 `snapshots` 为空数组。

## 恢复

```powershell
bulings delivery snapshot-restore --project <工程> --feature-id <id> --snapshot-id <哈希>
```

不带 `--execute` 时只预览，退出码 0：

```json
{
  "status": "preview",
  "archiveChanges": ["01-requirements/README.md"],
  "scopeChanges": ["Assets/Scripts/Reward/RewardView.cs"],
  "lease": "active"
}
```

`lease` 为 `none`、`active`、`in_review` 或 `circuit_open`。后三种在未执行时不改文件；一旦加 `--execute` 且租约不是 `none`，失败并保持 `LEASE_ACTIVE`。协调者应先按任务 09 结束租约。

`--execute` 且租约为 `none` 时：

1. 先做一次 `reason` 为 `before-overwrite` 的保存。
2. 用快照里的 `archive/` 替换当前档案中的对应文件。`snapshots.git` 目录本身不替换。
3. 若快照含 `scope/`，把其中文件写回工程相对路径。不删除当前工程里多出来的、不在该快照 `scope/` 中的文件。
4. 返回 `status` 为 `restored` 和新的当前快照标识，也就是第 1 步产生的保存点。

预览失败或执行中复制失败时，不留下部分替换。执行前把将被覆盖的文件复制到临时目录，失败则写回。

冻结交付项允许列表和预览。`--execute` 失败，`code` 为 `FROZEN`。

## 规则

`references/snapshot.md` 规定协调者在每个阶段第一次编辑前保存 `stage-start`；覆盖一批已有正文前保存 `before-overwrite`。保存成功不表示测试通过。

## 测试

- 连续两次相同保存返回同一提交。
- 修改需求总览后再保存，列表有两条，新的在前。
- 预览不改变需求总览字节。
- 无租约时执行恢复，总览回到旧正文，并且多了一条 `before-overwrite` 提交。
- 存在 `lease.json` 时执行恢复失败，总览字节不变。
- Unity 工程仓库的 HEAD 在保存和恢复前后相同。
