# 01 交付档案初始化

先读 [00-索引与共同约定](00-索引与共同约定.md)。本任务只建立交付项的目录和生命周期清单，并提供创建与只读查询。

## 目标

`bulings delivery init` 在 Unity 工程里创建一个交付项。重复执行已经完整的档案时不改文件。`bulings delivery status` 能在不带标识时列出交付项，带标识时返回这一项的清单摘要。

## 本任务产出

- `bulings/delivery/` 包，至少含路径校验、初始化、状态查询。
- `bulings delivery init` 与 `bulings delivery status`。
- `tests/test_delivery_archive.py`。

后续任务才会写入文档元数据、Skill、切片和租约。本任务生成的 Markdown 可以只有标题和一句「待填写」，不要设计前置元数据格式。

## 命令

```powershell
bulings delivery init --project <Unity工程> --feature-id building-interaction --title 建筑交互
bulings delivery status --project <Unity工程>
bulings delivery status --project <Unity工程> --feature-id building-interaction
```

`--project` 必须是含 `Assets` 和 `ProjectSettings` 的目录。`--feature-id` 遵守索引里的标识规则。`--title` 去首尾空白后非空。

`init` 成功时标准输出：

```json
{
  "status": "created",
  "featureId": "building-interaction",
  "archive": ".bulings/deliveries/building-interaction"
}
```

档案已经完整时 `status` 为 `unchanged`，文件修改时间不变。

## 档案内容

创建这些相对路径：

```text
.bulings/deliveries/<feature-id>/feature.json
.bulings/deliveries/<feature-id>/01-requirements/README.md
.bulings/deliveries/<feature-id>/01-requirements/terminology.md
.bulings/deliveries/<feature-id>/02-investigation/README.md
.bulings/deliveries/<feature-id>/03-design/README.md
.bulings/deliveries/<feature-id>/04-plan/README.md
.bulings/deliveries/<feature-id>/05-implementation/README.md
.bulings/deliveries/<feature-id>/06-validation/README.md
```

先写到同级临时目录 `.bulings/deliveries/.<feature-id>.tmp-<随机>`，全部成功后再改名为正式目录。失败时删除临时目录。正式目录已存在则不要另起临时目录。

`feature.json`：

```json
{
  "schema": 1,
  "featureId": "building-interaction",
  "title": "建筑交互",
  "profile": "delivery",
  "lifecycle": "draft",
  "createdAt": "2026-10-27T00:00:00+00:00",
  "updatedAt": "2026-10-27T00:00:00+00:00",
  "frozenAt": null,
  "retentionDays": 30,
  "validation": {
    "conclusion": "pending",
    "unverifiedBoundaries": "pending",
    "residualRisks": "pending"
  }
}
```

`profile` 固定为 `delivery`。界面配置由任务 12 增加取值，本任务只接受这一个值。

六份阶段 `README.md` 的一级标题分别是：需求、调查、设计、计划、实施、验证。`terminology.md` 的一级标题是「术语」，其下有「已确认术语」「候选术语」两个二级标题，正文先留空。

## 完整性

以下任一情况，`init` 在写入前失败，退出码 1，不补文件：

- 正式目录已存在，但缺少上表中的任一文件。
- `feature.json` 的 `schema` 不是 1，或 `featureId` 与目录名不一致。
- `profile` 不是 `delivery`。
- 任一路径是符号链接。

`status --feature-id` 读到同一类问题时同样失败，并在 `blockers` 里给出相对路径。

不带 `--feature-id` 的 `status` 只扫描 `.bulings/deliveries/` 的一级子目录。损坏的子目录出现在结果的 `invalid` 列表中，不导致整次查询失败。没有 `deliveries` 目录时返回空列表和空 `invalid`。

带标识的成功结果：

```json
{
  "featureId": "building-interaction",
  "title": "建筑交互",
  "profile": "delivery",
  "lifecycle": "draft",
  "archive": ".bulings/deliveries/building-interaction",
  "updatedAt": "2026-10-27T00:00:00+00:00"
}
```

不带标识的成功结果：

```json
{
  "deliveries": [
    {
      "featureId": "building-interaction",
      "title": "建筑交互",
      "lifecycle": "draft",
      "updatedAt": "2026-10-27T00:00:00+00:00"
    }
  ],
  "invalid": []
}
```

## 与工作模式的边界

不要读取或写入 `.bulings/runs/`。不要修改 `bulings run` 的参数。`workflow.yaml` 的 `mode: indie` 不阻止 `delivery init` 和 `delivery status`，因为这两条命令不启动 Agent。

## 测试

在临时 Unity 工程中覆盖：

- 首次 `init` 产生全部文件，JSON 可被再次读出。
- 第二次 `init` 返回 `unchanged`，`feature.json` 字节和时间戳不变。
- 非法标识、空标题、非 Unity 目录返回退出码 2 或 1，且不创建 `.bulings/deliveries`。
- 删掉一份阶段 README 后再 `init`，返回失败且不补写该文件。
- `status` 能列出多项；一项损坏时另一项仍出现在 `deliveries`。
- 现有 `tests/test_tasks.py`、`tests/test_config.py`、`tests/test_install.py` 通过。

库函数要能接受显式 `now`，测试不依赖当前时钟。
