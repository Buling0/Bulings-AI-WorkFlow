# 03 协调者入口

先读 [00-索引与共同约定](00-索引与共同约定.md)。前置是 [01-交付档案初始化](01-交付档案初始化.md)。本任务不依赖新鲜度命令；文档规则只引用阶段目录，不调用 `confirm-change`。

## 目标

增加一条必须显式使用的 Cursor Skill。协调者用它定位交付项、读取当前动作的规则，并在一个对话里只推进一个交付项。局部修改仍由 `work-feature` 处理。

## 本任务产出

- `pack/skills/delivery/SKILL.md`
- `pack/skills/delivery/references/coordinator.md`
- `bulings delivery rules --project <工程> --action coordinator`
- `bulings delivery open`：按标题或标识定位已有档案，没有匹配时不创建
- `tests/test_delivery_skill.py`

`rules` 按动作名读取 `references/<action>.md`。文件存在就返回该文件，不在代码里写死动作名单。后续任务只追加自己的规则文件。文件不存在时失败，不要预写那些动作的正文。

## Skill 行为

`SKILL.md` 的 front matter：

```yaml
---
name: delivery
description: 使用 Bulings 交付流推进需要分步实施和独立评审的 Unity 功能。仅在用户显式要求交付流、bulings delivery 或长任务交付时使用。
disable-model-invocation: true
---
```

正文用中文规定：

1. 用户没有明确要求走交付流时，改用 `work-feature`；若对方只是一点局部修改，就停在普通编辑，不运行 `delivery init`。
2. 当前对话只处理一个 `feature-id`。
3. 进入时运行 `bulings delivery open`。唯一匹配则继续；多个匹配则列出标题请用户选择；没有匹配且用户给出了要做的功能时，才运行 `delivery init`。
4. 接着运行 `bulings delivery status --feature-id`。若任务 02 已使 `status` 带上 `documentErrors`，有错误就先处理错误。
5. 用 `bulings delivery rules --action coordinator` 读取规则。规则命令返回的正文是动作规则的唯一来源，Skill 不复制第二份阶段说明。
6. 一次只推进状态给出的当前阶段。阶段顺序是需求、调查、设计、计划、实施、验证。本任务尚未有机器阶段字段，协调者以六份总览里第一份仍是「待填写」的阶段为当前阶段；都已写过时停在验证并说明后续验收命令还未安装。
7. 不创建 git commit，不改 `.meta` guid，不启动 Unity 批处理，不修改 `protectedPaths`。
8. `mode: indie` 时不启动 Agent。`open` 和 `rules` 仍可查询。

`references/coordinator.md` 写明六段职责，与 DLoop 说明第 6 节一致，用 Bulings 的目录名：

- 需求：用户要确认的目标、范围、验收和边界。
- 调查：仓库和环境能证明的事实与未知。
- 设计：基于需求和证据做出的方案、职责和行为。
- 计划：可分别验收的结果、顺序、依赖和回滚。
- 实施：工作区里的实际变化和执行结果。
- 验证：实际证据、结论、未验证边界和残留风险。

并写明：事实类型不能互相冒充；内容简单时只维护总览；交付档案不是长期知识库，用户没指定目标路径时不另写项目文档。

## 规则命令

```powershell
bulings delivery rules --project <工程> --action coordinator
```

成功输出：

```json
{
  "action": "coordinator",
  "rules": [
    {
      "path": "pack/skills/delivery/references/coordinator.md",
      "sha256": "sha256:<文件原始字节>",
      "body": "<完整正文>"
    }
  ]
}
```

`--project` 用来确认这是 Unity 工程。规则文件从安装包的 `pack/skills/delivery/references/` 读取，不从目标工程里的副本读取，避免工程内副本被改后和命令不一致。路径字段写仓库相对路径。

未知动作、文件不是 UTF-8、文件是符号链接时，整次失败，`rules` 不返回部分内容。

## 定位命令

```powershell
bulings delivery open --project <工程> --query 建筑交互
```

`--query` 与某档案的 `featureId` 全等，或与 `title` 全等，或是 `title` 的不区分大小写子串。唯一命中时返回任务 01 的单档案 `status` 对象，并加 `"match": "unique"`。多个命中时退出码 1，`code` 为 `MULTIPLE_MATCHES`，`candidates` 含 `featureId` 和 `title`。零命中时退出码 1，`code` 为 `NOT_FOUND`。该命令不创建档案。

## 测试

- Skill 文件存在，描述里包含「显式」，并且 `disable-model-invocation` 为 true。
- `rules --action coordinator` 返回的 `body` 与文件字节一致，摘要可复核。
- 未知动作失败且标准输出为空。
- 两个标题都包含同一子串时 `open` 返回多个候选。
- 标识全等优先于标题子串：查询串等于一个 `featureId` 时即使另一个标题包含该串，也返回唯一匹配。
- `bulings init` 到临时 Unity 工程后，`.cursor/skills/delivery/SKILL.md` 存在，原有 `work-feature` 仍在。
